# Copyhot 开发计划

状态：启动草案  
日期：2026-11-10  
配套文档：[技术架构设计](技术架构设计.md)、[开源合规评估](开源合规评估.md)

本文是产品与交付范围的约定。进程划分、数据模型和外发规则以架构文档为准。许可证能否使用以合规评估为准。三份文档冲突时，先改文档再写代码。

## 1. 目标

做一个纯 PC 桌面、本地优先、源码按 GNU GPL-3.0 发布的视频工具。用户给出一段自己有权使用的参考视频后，应用在本地提取节奏和镜头结构，仅在用户确认后用其自备的模型密钥做风格分析，生成可复用的剪辑模板。模板套到用户自己的素材上，生成 Shotcut 工程；修剪、分割、字幕和导出使用 Shotcut 已有的时间线，不另写一套剪辑器。

## 2. 非目标

首发不做以下事情：

- 抖音、哔哩哔哩、YouTube 等平台的下载、解析或爬取。
- 账号、登录、云同步、协作工程和业务服务端。
- 内置或代管共享模型密钥。应用不代理用户的密钥。
- 把参考片的画面、音轨或字幕原文写进模板。
- 重写时间线、预览、撤销栈或编码器。这些保持 Shotcut / MLT 的实现。
- 移动端、网页版和插件市场。
- 为闭源商用单独做一套 LGPL 裁剪构建。本项目按开源再分发评估依赖。

## 3. 用户与首发平台

使用者在本机完成「参考片 → 模板 → 用自己的素材出片 → 微调导出」。首发验收平台是 Windows 10/11 x64。Shotcut 已支持 macOS 与 Linux，构建能力保留，但不列入首发验收。

参考视频必须是用户选定的本地文件。开始分析前，界面要求用户确认自己有权为该用途处理这个文件。应用不判断版权归属，只保留这次确认的时间和文件标识在本地工程记录里。

## 4. 功能范围

### 4.1 热点分析与模板

本地阶段（不访问网络）：

- 读取时长、分辨率、帧率、音视频轨。
- 镜头切分与每段时长。
- 音量或节奏的粗统计，用于 BGM 强弱，不提取可播放的音频副本进模板。
- 按镜头抽取低分辨率关键帧，供后续确认是否外发。
- 用户另行打开时，可用本地转写得到文本，避免默认上传音轨。

用户确认外发清单之后，BYOK 调用只提交统计、文本和经同意的关键帧。模型必须返回约定的 JSON。校验失败则丢弃，不写入半截模板。默认不上传整文件。上传短视频或整文件必须另一次明确勾选。

模板描述风格和槽位：画幅与帧率、镜头时长序列、转场类型与时长、字幕样式与位置、BGM 槽位和增益。模板可以反复套用到不同素材。

### 4.2 本地素材库

- 用户指定素材库根目录。视频、图片、BGM 留在该目录或用户原来的路径，不复制进数据库。
- SQLite 只保存路径、内容标识、媒体信息、缩略图路径、标签和检索文本。
- 导入本身不调用 AI。AI 理解默认关闭，打开后仍按单次或批量任务展示外发范围，用户确认才发送。
- 检索使用本地全文索引。若模型返回向量，向量只存本地。

### 4.3 剪辑与微调

模板绑定素材库条目后，生成带 Shotcut 所需标注的 MLT XML 工程，并用现有时间线打开。首发要能在这条时间线上完成：

- 修剪、分割、移动、删除片段
- 替换镜头
- 音量
- 字幕文本
- 转场时长
- 导出

撤销沿用 Shotcut 的撤销栈。不在首发承诺调色、跟踪、多机位和关键帧曲线的新增能力；上游已经提供的滤镜可以照常使用，只是不作为 Copyhot 的验收项。

导出提供 AIGC 显式标识开关，默认开启。隐式元数据标识与「本地工具 + BYOK」是否属于标识义务主体，在合规评估中列为律师确认项，不在本文写成已经履行法定义务。

## 5. 技术路线

客户端是 Shotcut 的下游分支，语言和 UI 保持 C++ / Qt 6，媒体引擎保持 MLT 与上游已经集成的 FFmpeg。Copyhot 的新界面做成新的停靠面板和向导，通过现有的 Action、撤销命令和 `Mlt::Controller` 改时间线。

理由：Shotcut 的时间线、播放器、代理、字幕和导出已经可用，许可证是 GPL-3.0，可以被本开源项目使用和再分发。另起 Web 剪辑界面会丢掉这套能力，也会引入第二套媒体栈。

上游版本锁定到某个稳定标签，不跟随浮动 master。Copyhot 的新增代码集中在独立目录，只在主窗口注册菜单、面板和动作，便于以后合并上游。细节见架构文档。

## 6. 里程碑

里程碑按出口条件排列，不排日历。前一阶段出口未满足，不开始下一阶段的功能开发。

### M0 文档与上游验证

- 本计划、架构文档、合规评估已入库。
- 选定并记录一个 Shotcut 稳定标签。
- 在 Windows 上从该标签编译通过，打开本地素材，完成一次裁切并导出。
- 确认可以增加停靠面板，并且能用现有撤销命令或 MLT API 生成可打开的 `.mlt`。
- 抽样核对上游源文件的许可证声明，并列出随 Shotcut 分发的第三方声明来源（上游 credits）。
- 任一验证失败则只更新架构文档中的阻塞项，不进入 M1。

### M1 本地素材库

- 可选择库根目录并导入视频、图片、音频。
- 生成缩略图和基础媒体信息，写入 SQLite。
- 文件移动或缺失时，库中条目标为不可用，不崩溃。
- 此阶段没有网络请求，设置里也没有可用的模型调用。

### M2 BYOK 与素材理解

- 密钥只进操作系统凭据库，不明文出现在设置文件、工程、日志和崩溃信息里。
- 关闭 AI 时，导入和检索与 M1 一致。
- 打开后，对单条素材展示本次将发送的字段，确认后才请求；结果标签只写回本地库。
- 请求失败、拒绝或校验失败时，素材仍保留，仅没有 AI 标签。

### M3 参考片到模板

- 对本地参考片完成第 4.1 节的本地分析，用户能在发送前看到关键帧数量和文本是否包含在内。
- 默认路径不发送整文件；深度模式有单独勾选。
- 返回 JSON 通过 schema 后才能保存为模板；失败时界面保留本地分析结果，允许重试。

### M4 套用与微调导出

- 把模板槽位绑定到素材库条目，生成 `.mlt` 并用 Shotcut 时间线打开。
- 第 4.3 节列出的微调都能做，且可以撤销。
- 导出成片；显式 AIGC 标识开关默认开启。
- 参考片的图像和音频不出现在模板文件中。

### M5 开源分发

- 仓库包含 GPL-3.0 许可证文本、上游版权声明，以及与所分发二进制对应的构建说明。
- 关于对话框能打开第三方许可证。
- 提供 Windows 安装包，且同一版本的对应源码可以取得。
- 合规评估里的「排除项」依赖没有进入安装包。

## 7. 风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 参考片或成品涉及他人版权，或做成可下载的平台解析 | 内容侵权、违反平台条款 | 只接受本地文件；模板不含画面和音轨；不做下载器 |
| Shotcut 合并成本高，Qt / MLT 版本被上游抬升 | M0 之后功能开发被构建问题堵住 | 锁定标签；新代码独立目录；M0 先打通编译和导出 |
| 依赖许可证与 GPL-3.0 冲突，或条款禁止开源再分发 | 无法按本仓库许可证发布 | 新依赖先写入合规评估；禁止专有 SDK 和 CC-BY-NC、BUSL、SSPL、Commons Clause |
| H.264 / HEVC 等专利 | GPL 不授予专利权 | 沿用上游编解码构建；专利单列，不写成「已满足 GPL 即无专利风险」 |
| 境外多模态接口在国内不可用，或模型不返回稳定 JSON | 模板生成失败 | OpenAI 兼容 Base URL 可更换；schema 校验失败不落盘 |
| 大文件、代理和缩略图占满磁盘 | 导入或预览失败 | 代理沿用 Shotcut 现有策略；库与代理目录可改到用户指定盘 |
| 关键帧含人脸等敏感个人信息 | 超出用户预期的外发 | 发送画面单独同意；默认可不发送画面 |
| 生成式内容标识义务主体不清楚 | 导出合规不足或过度承诺 | 产品默认加显式标识；义务主体由律师确认 |
| Shotcut 几乎没有 C++ 单元测试 | 回归靠手工 | M0 起固定一条手工验收路径：打开、裁切、导出；EDL 相关沿用上游已有的 Node 测试 |

## 8. 文档与实现的衔接

M0 在验证上游之前只修改文档和构建记录。引入 Shotcut 树之后，行为变更要同时改架构文档里对应的小节，避免代码和三份文档各说各话。
